User Guide

GameMates helps gamers keep track of friends, their contact details, the games they play and their in-game usernames. Type commands to manage your friends, then use the split details panel to check who to invite to a game. Your data stays on your computer; browsing the online help and downloading releases require internet access.

This guide describes the commands available in this checkout. Adding or deleting individual games and game metadata input are not available yet. You can view and filter games already present in sample or saved data. See Your profile and game entries for the current limits.

Quick start

  1. Ensure that Java 25 or later is installed on your computer.
    Mac users: Ensure you have the precise JDK version prescribed here.

  2. Download the latest .jar file from here.

  3. Copy the file to the folder you want to use as the home folder for GameMates.

  4. Open a terminal, cd to the folder containing the JAR file, and run java -jar gamemates.jar.
    Keep launching from this folder: it is where GameMates reads and writes your data and preferences.
    A GUI similar to the one below should appear in a few seconds. Note how the app contains some sample data.

  5. Type a command in the command box and press Enter to execute it. For example, type help and press Enter to open the help window.
    Some example commands you can try:

    • list : Lists all contacts.

    • list g/Valorant : Lists friends who play Valorant.

    • gamelist 1 g/Valorant : Shows the first displayed friend’s Valorant card, if present.

    • add n/John Doe p/98765432 e/johnd@example.com : Adds a contact named John Doe to GameMates.

    • delete 3 : Deletes the 3rd contact shown in the current list.

    • clear : Deletes all friends and their games immediately, while keeping your profile.

    • exit : Exits the app.

  6. Refer to the Features section below for details of each command.

Features

Notes about the command format:

  • Words in UPPER_CASE are the parameters to be supplied by the user.
    For example, in add n/NAME, replace NAME with a value such as John Doe.

  • Items in square brackets are optional.
    For example, n/NAME [t/TAG] can be used as n/John Doe t/friend or as n/John Doe.

  • Items followed by …​ can appear zero or more times.
    For example, [t/TAG]…​ may be omitted, or written as t/friend or t/friend t/family.

  • Prefixed parameters can be in any order. Positional indices must come first.
    For example, if the command specifies n/NAME p/PHONE_NUMBER, p/PHONE_NUMBER n/NAME is also acceptable.

  • Use spaces between parameters and lower-case command words and prefixes. Do not type square or angle brackets. Quotes are not needed around multiword names. Use only the prefixes documented for each command.
  • Repeating a single-value n/, p/ or e/ parameter in add or edit is rejected, even with identical values. Tags may be repeated; identical tag values are applied once.

  • Friend indices refer to the current left-hand list and range from 1 to 2147483647. Run list to see all friends again before choosing an index. Zero, negative numbers, decimals, a leading + and larger integers are rejected.

  • Extraneous parameters for commands that take no parameters, such as help, exit, and clear, are ignored.
    For example, help 123 is interpreted as help.

  • Wide tables scroll horizontally on narrow screens. If you are using a PDF version, take care when copying commands across line breaks: spaces can be lost during copying.

Viewing friend details

The main window has two panels: the friend list on the left and a details panel on the right.

  • Click a friend in the left panel to view their name, phone number, email address, tags, games, and in-game usernames in the right panel.
  • On startup, the right panel shows your profile. If no profile details have been added, it shows No details added.
  • When a find command returns exactly one friend, that friend’s details are shown automatically.
  • Use gamelist FRIEND_INDEX [g/GAME_NAME] to select a friend and optionally show only one of their games. Clicking another friend shows all of that friend’s games.
  • Successful commands other than gamelist or a single-result find return the right panel to your profile. Clicking a friend selects their details again. Invalid commands keep the existing details display.
  • find and list g/GAME_NAME each replace the previous friend-list filter. They do not combine filters. Adding or editing a friend shows the full list again; deleting a friend keeps the current friend-list filter.

Your profile and game entries

Your profile is stored separately from your friend list. It appears on startup and after commands such as list. If it contains no details, the right panel shows No details added. Filtering, deleting friends and clear do not change your stored profile.

Use edit myself n/Joash to set your own name, or supply other supported edit fields to update your contact details and tags. The myself selector is case-insensitive and works even when the friend list is empty or filtered. Omitting the selector, as in edit n/Joash, is rejected. Profile edits preserve your games and the friend-list filter.

You can view games and usernames already loaded from saved data or the initial sample data using gamelist. New friends start with no games. gameadd and gamedel are not recognised commands in this build, and there is no metadata input or display yet. Deleting a friend removes that friend’s complete entry, including their games; it does not remove games from other friends. Back up your data before editing a saved file.

Viewing help: help

Opens a separate Help window with the online User Guide link. Click Copy URL and paste the link into a browser. You can also open Help using the menu or F1. The command feedback is Opened help window.

Format: help

Adding a friend: add

Adds a friend to GameMates.

Format: add n/NAME [p/PHONE_NUMBER] [e/EMAIL] [t/TAG]…

  • Only the name is required. Omitted phone and email details are shown as Not provided.
  • Supplied phone and email values must satisfy the validation rules. Empty p/ or e/ values are rejected.
  • Leading and trailing spaces are removed. Names must be unique, ignoring case and repeated spaces: John Doe and john doe identify the same friend.
  • A friend’s name must also differ from your Myself profile’s name under the same comparison rules.
  • Different friends may share a phone number or email address.
Tip: A friend can have any number of tags, including zero.

Examples:

  • add n/John Doe
  • add n/John Doe p/98765432 e/johnd@example.com
  • add n/Betsy Crowe t/friend e/betsycrowe@example.com p/1234567 t/criminal

Names are trimmed before validation, must not be blank and may contain at most 100 characters. Only ASCII letters, digits and spaces are accepted. Names are compared case-insensitively, so john doe and John Doe are the same friend. To distinguish two people with the same name, use names such as John Doe School and John Doe Work. Adding a different tag alone does not make a duplicate name unique; parentheses are not valid in names.

Tag names must be non-empty and contain only ASCII letters and digits (no spaces or symbols).

Phone numbers accept formats such as 91234567, +6591234567, +65 9123-4567 and (123) 456-7890.

  • Use 3–15 ASCII digits without +, or 2–15 with +, including the country code.
  • Put + at the start, immediately before a digit or (. The first digit after + must be 1–9.
  • Digit groups may have any length. Parentheses must enclose digits only and cannot be empty or nested.
  • Use at most one hyphen or space between groups. Separators may differ or be omitted. Leading, trailing and consecutive separators are rejected.
  • Dots, letters, non-ASCII digits and extensions are rejected.
  • Command input is trimmed. Saved numbers must already match these rules.
  • Formatting is preserved. +6591234567 and +65 9123-4567 are different phone values.
Validation checks format only, not country codes, national number lengths or whether a number is active. These rules also apply when editing friends and loading saved data.

Email addresses are trimmed before validation and must use ASCII local-part@domain syntax:

  • The entire address may contain at most 254 characters, with at most 64 before @.
  • The local part accepts letters, digits and the punctuation in !#$%&'*+/=?^_`{|}~-. Dots may separate non-empty parts, so leading, trailing and consecutive dots are rejected.
  • Each domain label (a part between dots) must contain 1–63 letters, digits or hyphens and must start and end with a letter or digit. Single-label domains such as user@localhost are accepted.
  • Quoted local parts, address literals such as user@[127.0.0.1], internal whitespace and non-ASCII characters are not supported. Validation checks format only, not whether a mailbox exists.
These rules use a practical subset of RFC 5322’s dot-atom syntax and RFC 5321’s SMTP length limits. The 254-character address limit leaves room for the enclosing < and > in the 256-octet SMTP path limit.

Listing and filtering friends: list

Shows all friends in GameMates, or filters the friend list by game.

Format: list [g/GAME_NAME]

  • list shows all friends and clears any previous friend-list filter. Feedback is Listed all friends., including when the list is empty.
  • list g/GAME_NAME shows friends who have a game with that exact name. The match is case-insensitive, so list g/valorant matches Valorant.
  • Leading and trailing spaces in GAME_NAME are ignored, but partial names do not match. For example, list g/Val does not match Valorant.
  • Only game names are matched; a friend’s in-game username is not matched.
  • Multi-word game names are accepted. Only one g/ prefix may be supplied, and the game name must not be empty.
  • If no friends play the specified game, the friend list is empty and the command reports 0 friend(s) listed!.
  • Filtering applies only to the friend list. It does not filter or modify the separately stored Myself profile.
  • Name filtering uses find, not list n/NAME. A new find or list replaces the previous friend-list filter; running them consecutively does not intersect their results.
  • Game-name validation uses the same 1–50-character rules as gamelist. Empty g/, extra positional input and repeated g/ are rejected. A valid filter returns N friend(s) listed!.

Examples:

  • list shows all friends.
  • list g/Valorant shows friends who play Valorant.
  • list g/Stardew Valley shows friends who play Stardew Valley.

Viewing a friend’s games: gamelist

Shows a friend’s details and game cards in the right panel, keeping the friend list and its current filter on the left. Each game card shows the game name and in-game username.

Format: gamelist <FRIEND_INDEX> [g/GAME_NAME]

  • Replace <FRIEND_INDEX> with a positive integer; do not type the angle brackets. The index is required and refers to the currently displayed friend list, including after find or list g/GAME_NAME.
  • Without g/, all of the selected friend’s games are shown. This also clears a previous game display filter.
  • With g/, only a game with the complete matching name is shown. Matching is case-insensitive: valorant matches Valorant, but Val does not. Usernames are not searched.
  • Leading and trailing whitespace in the game name is removed. Game names may contain 1–50 printable characters and must include at least one letter or digit. Multiword names are accepted.
  • Put the index before the optional filter. Only one g/ is allowed, even if repeated values are identical. Unknown prefixes and extra words before g/ are rejected. All words after g/ form the game name; whitespace-separated tokens such as x/ are treated as parameter prefixes, not part of the name.
  • An absent game is a successful empty result, including when the friend has no games. Stored friend details, game entries and your Myself profile are unchanged. Invalid commands leave the previous details display unchanged.

Examples:

  • gamelist 1 shows all games of the first displayed friend.
  • gamelist 2 g/Valorant shows only the second displayed friend’s Valorant entry.
  • gamelist 2 g/minecraft matches the stored name Minecraft.
  • gamelist 1 g/Stardew Valley accepts a multiword name.
  • find David followed by gamelist 1 shows the games of the first friend in those search results.
  • list g/Minecraft followed by gamelist 1 shows all games of the first displayed Minecraft player, while the left panel continues showing only Minecraft players.

Feedback (placeholders below are replaced with actual values):

Result Feedback
All games Listed GAME_COUNT game(s) that FRIEND_NAME plays:
Matching game Showing GAME_NAME for FRIEND_NAME: (uses the stored game-name spelling)
No matching game FRIEND_NAME does not have GAME_NAME. (uses your trimmed filter); the panel shows No matching game: GAME_NAME
No games, without a filter FRIEND_NAME has no games added yet.; the panel shows No games added

Errors:

gamelist myself is not supported; the existing profile view remains available when no friend is selected.

Editing a friend or your own profile: edit

Edits an existing friend or your separately stored Myself profile in GameMates.

Format: edit FRIEND_INDEX|myself [n/NAME] [p/[PHONE_NUMBER]] [e/[EMAIL]] [t/TAG]…

  • Edits the friend at the specified FRIEND_INDEX. The index refers to the index number shown in the displayed friend list. The index must be a positive integer 1, 2, 3, …​
  • Use myself instead of FRIEND_INDEX to edit your own profile, for example edit myself n/Alex Tan. The selector is case-insensitive.
  • | means “or”: enter either a friend index or myself. Do not type the | character.
  • At least one of the optional fields must be provided.
  • Supplied values are trimmed and validated using the same rules as add.
  • Omitted fields remain unchanged. Enter p/ or e/ without a value to remove that contact detail.
  • A name cannot be removed. The new name must be unique among other friends, ignoring case and repeated spaces.
  • Your own profile’s name must also be unique among all friends, ignoring case and repeated spaces. Adding or renaming a friend to match your own profile’s name is rejected.
  • Games remain unchanged when editing friend details.
  • Success feedback starts with Edited NAME and lists only changed details. Removed contact details are reported as removed phone number or removed email.
  • A friend index or myself is required. Editing Myself works even when no friends are displayed and preserves the current friend-list filter.
  • Omit t/ to keep the friend’s existing tags. Each supplied t/TAG removes that tag if the friend already has it, or adds it if they do not. Other tags remain unchanged.
  • Tag matching is case-sensitive. Repeating the same tag in one command applies it only once.
  • To remove all of a friend’s tags, enter t/ without a tag after it. Use that empty prefix on its own; combining it with non-empty tags is rejected.
  • A successful friend edit shows all friends again, preserving the friend’s games and your profile. A successful edit myself shows your updated profile on the right and keeps the current friend-list filter.

Examples:

  • edit 1 p/91234567 e/johndoe@example.com Edits the phone number and email address of the 1st friend to be 91234567 and johndoe@example.com respectively.
  • edit 2 n/Betsy Crower t/ Edits the name of the 2nd friend to be Betsy Crower and clears all existing tags.
  • edit 2 p/ e/ removes the 2nd friend’s phone number and email.
  • edit 2 t/teammate removes teammate if the 2nd friend already has it, or adds it otherwise. Other tags remain unchanged.
  • edit myself n/Alex Tan p/91234567 updates your own name and phone number.
  • edit myself p/ e/ t/ clears your own phone number, email and tags while preserving your name and games.

Errors:

  • Missing index: Please provide an index.
  • Invalid index: Index must be a positive integer.
  • Empty displayed list: No friends are currently displayed. Use list to show all friends.
  • Index outside the displayed list: No friend exists at index INDEX. Choose an index from 1 to MAX_LIST_INDEX.
  • No fields provided: No details were passed to the command. Specify at least one parameter ([n/NAME], [p/[PHONE]], [e/[EMAIL]], [t/TAG]...) to edit specific details.
  • Duplicate name: This friend already exists in GameMates.
  • Adding or renaming a friend to your profile’s name: This name is already used by your Myself profile.

Locating friends by name: find

Finds friends whose names contain any of the given keywords.

Format: find KEYWORD [MORE_KEYWORDS]

  • The search is case-insensitive; for example, hans matches Hans.
  • Keyword order does not matter; for example, Hans Bo matches Bo Hans.
  • The search considers only names.
  • Only full words match; for example, Han does not match Hans.
  • Friends matching at least one keyword are returned (an OR search); for example, Hans Bo returns Hans Gruber and Bo Yang.
  • Searching starts from all friends, replacing any previous name or game filter. find does not accept n/ or g/ as filter syntax; such text is treated as literal name keywords.
  • Feedback is N friend(s) listed!. No matches is a successful empty list. Exactly one result also opens that friend’s complete details and games on the right. An empty keyword list is rejected with usage instructions.

Examples:

  • find John returns john and John Doe
  • With the initial sample data, find alex david returns Alex Yeoh, David Li.

Deleting a friend: delete

Deletes the specified friend from GameMates.

Format: delete FRIEND_INDEX

  • Deletes the friend at the specified FRIEND_INDEX.
  • The index refers to the index number shown in the displayed friend list.
  • The index must be a positive integer 1, 2, 3, …​
  • Leading and trailing spaces are ignored. The index must have a value from 1 to 2147483647.
  • A successful deletion displays Successfully deleted FRIEND_NAME.
  • Deletion happens immediately, with no confirmation dialog and no undo command. The friend’s games are deleted with the friend; other friends and your stored profile are preserved. The current friend-list filter stays active.

Examples:

  • list followed by delete 2 deletes the 2nd friend in GameMates.
  • find Betsy followed by delete 1 deletes the 1st friend in the results of the find command.

Errors:

  • Missing index: Please provide an index.
  • Invalid index (such as 0, -1, or abc), extra arguments, or a value above 2147483647: Index must be a positive integer.
  • Index outside the displayed list, including an empty list: The friend index provided is invalid.

Clearing the friend list: clear

Clears all friends from GameMates and preserves your Myself profile.

Format: clear

The command takes effect immediately, with no confirmation or undo. Feedback is Friend list has been cleared!. All friends and their game entries are removed. Back up your data file first if you may need them again.

Exiting the program: exit

Exits the program.

Format: exit

Saving the data

GameMates saves the complete friend list, games and stored profile after every command that parses and executes successfully, including viewing commands such as list and gamelist. You do not need a save command. The active friend-list filter, selection and game display filter are not saved; a new launch shows all friends and your profile. Window size and position are stored separately in preferences.json when you close the main window or use exit.

If saving fails, an error beginning Could not save data appears. A friend change may already be visible in the running application even though it was not written to disk. Restore write access to the data folder and run a successful command such as list to try saving again before closing the app.

Editing the data file

GameMates uses data/gamemates.json relative to the folder from which you launch it. If you follow Quick start, this is the folder containing the JAR. Launching the same JAR from a different folder uses different data. The status bar shows the data path. Friends are stored under friends, and your profile is stored under myself.

To back up or transfer your data, close the app and copy data/gamemates.json to a safe location. To restore it, close the destination app, back up its current file, replace it with your copy and relaunch from the same folder. Copy preferences.json only if you also want the saved window settings.

If you edit JSON manually, close the app first and keep a backup. Friend entries contain name, optional phone and email, tags, and games. A game has a name and username. Existing files that omit games load with no games; files that omit myself use the default empty profile. Empty or missing contact fields mean Not provided. Use the same validation rules as command input. Stored game metadata is supported as an optional metas array, for example "metas": [{"key": "Role", "value": "Support:Mid"}]. Keys contain 1–50 characters and values 1–200 after trimming, with at least one letter or digit and no control characters. Keys cannot contain colons and must be unique per game, ignoring case; values may contain colons. Missing metas loads as empty. Metadata is preserved when saving, but cannot yet be entered through commands or viewed in game cards.

Caution: If the file is missing, the app starts with sample friends and the default profile. If it cannot load the file because of malformed JSON or invalid stored values, it starts with an empty friend list and default profile. The original file is not automatically repaired or backed up. The next successful command can overwrite it with the current data, so close the app and restore your backup before entering commands if you need to recover it. Unknown JSON fields are ignored and are not preserved on the next save. Use the supported metas format for metadata.

Archiving data files [coming in v2.0]

Future proposal only: automatic archiving is not implemented. Use the manual backup procedure above.

FAQ

Q: How do I transfer my data to another computer?
A: Follow the backup and restore steps in Editing the data file. Keep both apps closed while copying the file, then launch the destination app from its usual data folder.

Known issues

  1. When using multiple screens, if you move the application to a secondary screen, and later switch to using only the primary screen, the GUI will open off-screen. The remedy is to delete the preferences.json file created by the application before running the application again.
  2. If you minimize the Help Window and then run the help command (or use the Help menu, or the keyboard shortcut F1) again, the original Help Window will remain minimized, and no new Help Window will appear. The remedy is to manually restore the minimized Help Window.
  3. A data file containing only null can prevent startup. The usual empty-data fallback does not handle this case. Close the app and restore a valid data/gamemates.json backup before relaunching.
